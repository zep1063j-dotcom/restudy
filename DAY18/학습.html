글 한 편 보기 만들기

이 페이지의 코드는 강의 개념을 바탕으로 새로 구성한 연습 예제입니다.

전체 목차기초 용어·들여쓰기 안내예제만 새 탭에서 열기
기초 정의핵심 정리코드 수정·실행복습문제

01. 핵심 개념

요청 주소·메서드·응답 상태, fetch, response.ok, JSON, 오류 처리

02. 실행 흐름

요청 → 응답 상태 검사 → JSON 읽기 → 화면 반영 / 실패 안내 → 마무리

기초부터 천천히 읽기

서버 통신 코드를 읽을 때는 주소, 요청 방법, 응답 상태, 응답 본문을 따로 찾습니다. 요청이 끝났다는 사실만으로 화면에 필요한 데이터가 준비됐다고 생각하지 않습니다.

처음 보는 말의 정확한 뜻

URL과 엔드포인트
URL은 자원의 주소입니다. API 문맥에서 특정 기능이나 데이터를 요청하는 주소를 엔드포인트라고 부릅니다.
메서드
GET·POST 등 요청의 의도를 표현하는 방법입니다. 실제 API가 어떤 메서드와 데이터를 요구하는지 확인해야 합니다.
상태 코드
200·404·500처럼 응답의 결과를 나타내는 숫자입니다. 404는 못 찾음, 500은 서버 쪽 오류를 나타내는 대표적인 코드입니다.
본문과 헤더
본문은 실제 전달할 데이터이고 헤더는 형식 같은 부가 정보를 담습니다. Content-Type은 본문 형식을 읽는 단서입니다.
네트워크 실패와 HTTP 오류
응답을 받지 못한 연결 문제와, 응답은 받았지만 상태가 오류인 경우는 다릅니다. fetch와 ok 검사 위치를 나누어 봅니다.
finally
try/catch의 성공·실패 경로와 관계없이 마무리 코드를 둘 때 사용합니다. 로딩 표시 해제 등을 정리하는 데 쓰입니다.

기호와 문법을 읽는 법

같은 기호도 문맥에 따라 역할이 달라집니다. 아래 설명은 이 페이지의 예제 기준입니다.

짧은 코드 한 줄씩 읽기

const response = await fetch(url);

if (!response.ok) {
  throw new Error(`상태 ${response.status}`);
}

const post = await response.json();
  1. async 함수 안에서 url이 정의되어 있다는 전제입니다.
  2. 응답 뒤 3줄에서 상태를 확인하고 오류면 던집니다. 이 오류를 받는 catch가 주변에 있는지 봅니다.
  3. 정상일 때만 본문을 JSON으로 읽습니다. post가 받은 데이터의 구조와 맞는지도 이후에 확인합니다.

예상 결과와 전제

정상 JSON이면 post가 JavaScript 값이 됩니다. 404 응답은 직접 던진 오류 경로로 가며, 본문이 잘못된 JSON이어도 읽기 단계에서 실패할 수 있습니다.

먼저 알아둘 용어와 정의

코드 전체를 외우기보다, 각 이름이 무엇을 가리키는지 연결해서 읽어 보세요.

API
다른 기능이나 데이터와 정해진 방식으로 상호작용하는 인터페이스입니다. 여기서는 웹 요청과 응답을 통해 데이터를 받는 맥락입니다.
HTTP 요청과 응답
요청에는 주소·메서드 등이 있고, 응답에는 상태 코드·헤더·본문 등이 있습니다.
fetch
요청을 시작하고 Response로 이행되는 Promise를 돌려주는 브라우저 API입니다.
response.ok
응답 상태가 200~299인지 확인하는 값입니다. 응답을 받았다는 것과 업무 처리가 성공했다는 것을 구분해서 봅니다.
response.json()
응답 본문을 읽어 JavaScript 값으로 해석하는 비동기 메서드입니다.
try / catch / throw
실패할 수 있는 작업을 try에 두고, throw나 거부된 Promise의 오류를 catch에서 처리합니다.

꼭 기억할 내용

  • 404나 500도 서버의 응답입니다. fetch가 자동으로 모두 catch에 보내는 것이 아니므로 ok나 status를 확인합니다.
  • fetch 응답 대기와 JSON 본문 읽기는 서로 다른 단계입니다. 두 await의 역할을 구분하세요.
  • 이 예제는 실제 서버 대신 데이터 URL과 new Response로 만든 가상 404를 사용합니다.
이 예제의 코드를 읽는 순서
  1. 불러오기를 누르면 상태 문구를 바꿉니다.
  2. 선택한 모드에 따라 정상 데이터 URL 또는 가상 404 응답을 준비합니다.
  3. ok가 아니면 오류를 던지고, 정상이면 본문을 JSON으로 읽습니다.
  4. 성공은 글 제목, 실패는 안내 문구를 화면에 씁니다.

자주 헷갈리는 부분

응답이 왔으니 데이터도 이미 객체일까요?

Response와 읽어 낸 본문 데이터를 구분하세요. .json()도 기다려야 합니다.

JSON 읽기 오류도 생길 수 있을까요?

응답 본문이 JSON 형식이 아니면 해석에 실패할 수 있습니다.

로컬 실행에 맞게 일부를 재구성했습니다. 예제 안의 안내에서 실제 라이브러리·서버·파일 모듈과 다른 부분을 확인하세요.

03. 직접 바꿔 보기

정상 응답과 없는 글을 각각 실행하세요. JSON 데이터의 title을 내 문구로 바꿔 보세요.

먼저 결과를 예상하고 한두 줄만 바꿔 보세요. 화면 편집 내용은 이 브라우저에 자동 저장됩니다. 브라우저가 저장을 제한하면 저장되지 않을 수 있습니다.

코드는 안쪽 단계마다 두 칸씩 들여씁니다. 한 줄이 길면 가로로 움직여 읽을 수 있습니다. 수정한 코드도 ‘들여쓰기 정리’로 정돈할 수 있으며, 저장해 둔 초안은 자동으로 바꾸지 않습니다.
