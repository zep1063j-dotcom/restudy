DAY 07 / 읽기 · 수정 · 실행

내 페이지를 GitHub에 공개하기

이 페이지의 코드는 강의 개념을 바탕으로 새로 구성한 연습 예제입니다.

전체 목차기초 용어·들여쓰기 안내예제만 새 탭에서 열기
기초 정의핵심 정리코드 수정·실행복습문제

01. 핵심 개념

변경 확인, stage·commit·push, 브랜치·PR·충돌

02. 실행 흐름

파일 수정 → 변경 내용 확인 → 기록할 변경 선택 → 로컬 기록 → 원격 업로드

기초부터 천천히 읽기

Git의 명령은 파일 내용이 아니라 변경 이력에 동작합니다. 파일을 저장하는 단계, 커밋으로 기록하는 단계, 원격에 전송하는 단계를 나누어 이해하면 AI가 만든 변경도 검토하기 쉽습니다.

처음 보는 말의 정확한 뜻

저장소
Git이 관리하는 프로젝트와 변경 기록의 묶음입니다. 일반 폴더와 Git 저장소의 역할을 구분합니다.
로컬과 원격
로컬은 내 컴퓨터에 있는 저장소이고 원격은 네트워크로 연결된 다른 저장소입니다. GitHub에 올리기 전에도 로컬 커밋을 만들 수 있습니다.
커밋
선택한 변경을 하나의 이력으로 남긴 기록입니다. 메시지와 식별자를 통해 어떤 작업인지 다시 찾을 수 있습니다.
origin과 upstream
원격 저장소에 붙이는 별명입니다. 보통 origin은 내 원격, 수업에서는 upstream을 강사 저장소로 쓰지만 이름 자체가 소유자를 보장하지는 않습니다.
merge와 충돌
서로 다른 작업 흐름을 합치는 것이 merge입니다. 같은 부분에 양립하기 어려운 변경이 있으면 사람이 의도를 확인해 해결할 수 있습니다.
PR
변경을 검토하고 합치도록 제안하는 협업 절차입니다. 변경 비교와 논의에 쓰이며 로컬 커밋과는 다릅니다.

기호와 문법을 읽는 법

같은 기호도 문맥에 따라 역할이 달라집니다. 아래 설명은 이 페이지의 예제 기준입니다.

DAY07 기호와 예시
표기뜻짧은 예
gitGit 도구를 부릅니다.git status
add기록할 변경을 스테이지에 반영합니다.git add index.html
-m커밋 메시지 옵션입니다.git commit -m "소개 수정"
diff차이를 비교합니다.git diff
push연결된 원격에 커밋을 전송합니다.git push

짧은 코드 한 줄씩 읽기

git status
git diff
git add index.html
git commit -m "소개 문구 변경"
  1. 1줄은 변경 상태를 보고 2줄은 아직 스테이지에 올리지 않은 변경을 비교합니다.
  2. 3줄은 index.html의 현재 변경을 스테이지에 반영합니다. 다른 파일 전체를 무조건 포함한다는 뜻은 아닙니다.
  3. 4줄은 스테이지의 내용을 로컬 이력으로 기록합니다. 여기에 push는 포함되어 있지 않습니다.

예상 결과와 전제

명령이 성공하면 “소개 문구 변경”이라는 메시지를 가진 로컬 커밋이 생깁니다. 이 페이지에서는 명령을 실제로 실행하지 않습니다.

아래 실행 편집기에는 실행 가능한 전체 예제가 있습니다. 위 짧은 코드는 개념 설명용 발췌이며, 필요한 주변 코드와 전제를 함께 읽어 주세요.

먼저 알아둘 용어와 정의

코드 전체를 외우기보다, 각 이름이 무엇을 가리키는지 연결해서 읽어 보세요.

Git
파일의 변경 이력을 기록하고 비교하는 도구입니다. 언제 무엇을 바꿨는지 살펴볼 수 있습니다.
GitHub
Git 저장소를 원격으로 보관하고 협업하는 서비스입니다. Git 자체와 같은 뜻은 아닙니다.
작업 폴더 / 스테이지 / 커밋
작업 폴더에서 수정하고, 스테이지에 기록할 변경을 고른 뒤, commit으로 로컬 이력에 남깁니다.
브랜치
별도의 작업 흐름을 만들기 위한 이름입니다. 기능 수정 등을 나누어 진행하고 나중에 합칠 수 있습니다.
push / pull
push는 내 커밋을 원격으로 올리고, pull은 원격 변경을 받아 현재 작업 흐름에 통합하는 동작입니다.
diff
두 상태 사이에서 어떤 줄이 추가·삭제·수정되었는지 비교한 결과입니다.

꼭 기억할 내용

  • AI에게 수정을 맡긴 뒤에도 diff에서 요청과 관련 없는 변경이 섞였는지 확인하세요.
  • 커밋 메시지는 “수정”보다 “소개 문구 변경”처럼 나중에 이해할 수 있는 표현으로 남깁니다.
  • 이 페이지의 명령어는 읽기용 텍스트입니다. 실행 버튼이 Git 명령을 실행하지는 않습니다.
이 예제의 코드를 읽는 순서
  1. git status로 어떤 파일이 달라졌는지 확인하는 단계를 읽습니다.
  2. git diff로 줄 단위 변경을 비교합니다.
  3. git add로 고르고 commit으로 로컬에 기록한 뒤 push로 원격에 올리는 차이를 설명합니다.

자주 헷갈리는 부분

commit을 하면 바로 인터넷에 올라갈까요?

아닙니다. 로컬 기록과 원격 업로드는 별개입니다.

저장소에 올리면 웹사이트도 항상 즉시 바뀔까요?

웹 공개에는 배포 설정과 과정이 따로 관련될 수 있습니다.

03. 직접 바꿔 보기

HTML 안의 커밋 메시지를 더 구체적인 문구로 고쳐 보세요. 이 화면에서는 Git 명령이 실행되지 않습니다.

먼저 결과를 예상하고 한두 줄만 바꿔 보세요. 화면 편집 내용은 이 브라우저에 자동 저장됩니다. 브라우저가 저장을 제한하면 저장되지 않을 수 있습니다.

코드는 안쪽 단계마다 두 칸씩 들여씁니다. 한 줄이 길면 가로로 움직여 읽을 수 있습니다. 수정한 코드도 ‘들여쓰기 정리’로 정돈할 수 있으며, 저장해 둔 초안은 자동으로 바꾸지 않습니다.

04. 복습문제

commit만 하면 GitHub의 코드도 바뀔까?

내가 답한 뒤 해설 보기

아니다. commit은 로컬 기록이고 원격 반영은 push 단계다. 공개 화면 갱신은 별도의 배포 과정이 관련될 수 있다.
