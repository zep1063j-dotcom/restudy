DAY 17 / 읽기 · 수정 · 실행

도서 대출 확인 만들기

이 페이지의 코드는 강의 개념을 바탕으로 새로 구성한 연습 예제입니다.

전체 목차예제만 새 탭에서 열기

01. 핵심 개념

Promise, async·await, 성공·실패, 타이머

02. 실행 흐름

확인 시작 → 기다리는 동안 나머지 작업 → 완료·실패 후 이어서 실행

먼저 알아둘 용어와 정의

코드 전체를 외우기보다, 각 이름이 무엇을 가리키는지 연결해서 읽어 보세요.

비동기
시간이 걸리는 작업의 결과를 나중에 이어 받아 처리하는 방식입니다. 다른 실행 가능한 작업은 계속 진행할 수 있습니다.
Promise
나중에 완료될 결과를 표현하는 객체입니다. 대기(pending) 뒤 성공(fulfilled) 또는 실패(rejected)로 결정됩니다.
resolve / reject
Promise를 성공 또는 실패로 결정하는 함수입니다.
async / await
async 함수는 Promise를 돌려줍니다. await는 해당 함수 안에서 Promise가 결정된 뒤 이어지는 코드를 실행하게 합니다.
setTimeout
일정 시간이 지난 뒤 콜백 실행을 예약합니다. 정확히 그 시간에 즉시 실행된다고 보장하지는 않습니다.
콜스택과 이벤트 루프
현재 실행 중인 함수의 처리와 나중에 준비된 작업을 이어 실행하는 구조를 이해하는 개념입니다.

꼭 기억할 내용

  • await가 기다리는 것은 해당 async 함수의 이어지는 실행입니다. 브라우저 전체가 멈춘다는 뜻은 아닙니다.
  • 대기 중 문구와 버튼 비활성화를 함께 읽으면 중복 클릭 처리도 이해할 수 있습니다.
  • 이 예제의 1초 대기는 타이머로 만든 연습입니다. 실제 도서 서버를 조회하지 않습니다.
이 예제의 코드를 읽는 순서
  1. 버튼을 누르면 버튼을 잠시 비활성화하고 확인 중 문구를 씁니다.
  2. checkBook이 1초 뒤 성공하도록 예약한 Promise를 돌려줍니다.
  3. await가 끝난 뒤 받은 문구를 표시합니다.
  4. 버튼을 다시 사용할 수 있게 합니다.

자주 헷갈리는 부분

async를 붙이면 함수의 모든 줄이 나중에 실행될까요?

함수는 호출되면 실행을 시작합니다. await로 결과를 기다리는 지점과 그 뒤의 흐름을 나눠 읽으세요.

setTimeout의 1000은 정확한 종료 시각일까요?

최소 대기 시간으로 생각하세요. 다른 작업 상황에 따라 콜백 실행은 더 늦어질 수 있습니다.

03. 직접 바꿔 보기

대기 시간을 1000에서 2000으로 바꾸세요. 기다리는 동안 보이는 문구도 수정하세요.

먼저 결과를 예상하고 한두 줄만 바꿔 보세요. 화면 편집 내용은 이 브라우저에 자동 저장됩니다. 브라우저가 저장을 제한하면 저장되지 않을 수 있습니다.

04. 복습문제

await를 만나면 브라우저의 모든 JavaScript가 멈출까?

내가 답한 뒤 해설 보기

아니다. 해당 async 함수의 이어지는 부분이 기다린다. 다른 실행 가능한 작업은 계속 진행할 수 있다.
