오즈 카페 — 프로젝트 시작

이 페이지의 코드는 강의 개념을 바탕으로 새로 구성한 연습 예제입니다.

전체 목차기초 용어·들여쓰기 안내예제만 새 탭에서 열기
기초 정의핵심 정리코드 수정·실행복습문제

01. 핵심 개념

Node.js·npm·nvm, scripts, 개발 서버, 프로젝트 파일 구조

02. 실행 흐름

프로젝트 준비 → 의존 패키지 설치 → 개발 서버 → index.html → main.jsx → App

기초부터 천천히 읽기

React는 화면을 구성하는 도구이고 Node.js·npm·Vite는 개발을 돕는 환경과 도구입니다. 어떤 코드는 브라우저에서, 어떤 명령은 터미널에서 실행하는지 나누어 읽는 것이 먼저입니다.

처음 보는 말의 정확한 뜻

터미널과 현재 폴더
명령을 입력하는 프로그램입니다. npm 명령을 실행할 때 어느 프로젝트 폴더에 있는지가 중요합니다.
node_modules
프로젝트가 설치한 패키지들이 놓이는 폴더입니다. 보통 소스 저장소에 그대로 올리기보다 의존 정보에서 다시 설치합니다.
scripts
package.json에서 명령 이름을 정의하는 항목입니다. npm run dev는 dev라는 이름에 지정한 실제 명령을 실행합니다.
npm install과 npm run
install은 패키지 준비이고 run은 scripts의 명령 실행입니다. 설치 성공이 앱 실행이나 배포 완료를 뜻하지 않습니다.
진입점
프로그램이 시작되는 연결 지점입니다. 수업의 index.html·main.jsx·App.jsx가 어떻게 이어지는지 찾습니다.
createRoot와 render
React가 관리할 DOM 대상에 루트를 만들고 컴포넌트를 렌더하는 연결입니다. 대상 root 요소의 id가 맞아야 합니다.

기호와 문법을 읽는 법

같은 기호도 문맥에 따라 역할이 달라집니다. 아래 설명은 이 페이지의 예제 기준입니다.

DAY27 기호와 예시
표기뜻짧은 예
npm install터미널에서 의존 패키지를 준비하는 명령입니다.npm install
npm run devdev 스크립트를 실행합니다.npm run dev

짧은 코드 한 줄씩 읽기

function App() {
  return (
    <main>
      <h1>나의 카페</h1>
    </main>
  );
}
  1. App은 대문자로 시작하는 컴포넌트 함수입니다.
  2. return 뒤 괄호는 여러 줄의 JSX 표현식을 묶고, 그 안에서 main이 h1을 감쌉니다.
  3. 이 함수 정의만으로 화면에 보이는 것은 아닙니다. 예제 아래의 createRoot(...).render(<App />) 연결까지 확인합니다.

예상 결과와 전제

실제 root 렌더 연결을 실행하면 “나의 카페” 제목이 보입니다. 이 복습 폴더에서는 로컬 변환 도구를 사용하며 Vite 서버는 켜지 않습니다.

아래 실행 편집기에는 실행 가능한 전체 예제가 있습니다. 위 짧은 코드는 개념 설명용 발췌이며, 필요한 주변 코드와 전제를 함께 읽어 주세요.

먼저 알아둘 용어와 정의

코드 전체를 외우기보다, 각 이름이 무엇을 가리키는지 연결해서 읽어 보세요.

Node.js
브라우저 밖에서 JavaScript를 실행하는 환경입니다. 개발 도구를 실행할 때도 사용합니다.
npm / nvm
npm은 패키지와 프로젝트 명령을 관리하고, nvm은 Node.js 버전을 설치·전환하는 도구입니다.
개발 서버
작성한 소스를 브라우저에서 확인하도록 제공하는 개발용 서버입니다. 수업에서는 Vite를 사용합니다.
index.html / root
브라우저가 읽는 문서와 React가 화면을 넣을 대상 요소입니다. 이 예제는 id="root"를 사용합니다.
컴포넌트
화면의 한 부분을 설명하는 React 함수입니다. 보통 대문자로 시작하는 이름을 쓰고 JSX를 반환합니다.
JSX
JavaScript 안에서 화면 구조를 HTML과 비슷하게 적는 문법입니다. 브라우저 실행 전에 변환 과정이 필요합니다.

꼭 기억할 내용

  • 이 페이지는 설치 없이 읽도록 React와 JSX 변환 도구를 폴더에 포함했습니다. Vite 프로젝트 설치·실행 과정을 그대로 재현하지는 않습니다.
  • 컴포넌트 함수가 반환하는 내용과, 그 컴포넌트를 실제 root에 렌더하는 줄을 구분하세요.
  • 외부 패키지를 가져온 프로젝트에서는 해당 폴더의 package.json과 명령을 먼저 확인합니다.
이 예제의 코드를 읽는 순서
  1. root 요소가 처음에는 비어 있는 것을 확인합니다.
  2. 로컬 React와 변환 도구를 불러옵니다.
  3. App이 제목과 소개 문장을 포함한 JSX를 반환합니다.
  4. createRoot(...).render(<App />)가 App의 내용을 root에 그립니다.

자주 헷갈리는 부분

JSX 파일은 HTML 파일처럼 아무 브라우저에서 바로 해석될까요?

JSX는 변환이 필요합니다. 이 복습 예제와 수업의 Vite는 변환 방법이 다릅니다.

npm run dev와 배포는 같은 뜻일까요?

개발 중 화면 확인과 실제 서비스 배포는 다른 과정입니다.

실제 React와 JSX를 사용합니다. 로컬에 포함한 React와 변환 도구로 실행하며, 강의의 Vite 설치 절차를 재현한 것은 아닙니다. 화면 편집기에서 JSX도 바꿀 수 있습니다.

03. 직접 바꿔 보기

App이 반환하는 h1과 p의 내용을 내 가게로 바꾸세요.

먼저 결과를 예상하고 한두 줄만 바꿔 보세요. 화면 편집 내용은 이 브라우저에 자동 저장됩니다. 브라우저가 저장을 제한하면 저장되지 않을 수 있습니다.

코드는 안쪽 단계마다 두 칸씩 들여씁니다. 한 줄이 길면 가로로 움직여 읽을 수 있습니다. 수정한 코드도 ‘들여쓰기 정리’로 정돈할 수 있으며, 저장해 둔 초안은 자동으로 바꾸지 않습니다.
