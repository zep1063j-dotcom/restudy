오즈 카페 — 담기

이 페이지의 코드는 강의 개념을 바탕으로 새로 구성한 연습 예제입니다.

전체 목차예제만 새 탭에서 열기

01. 핵심 개념

state·set 함수·스냅샷, 불변성, Effect·의존성·정리 함수, 공통 부모

02. 실행 흐름

담기 → 자식이 전달받은 함수 호출 → App의 state 갱신 요청 → 새 값으로 렌더 → Header 갱신 → Effect로 탭 제목 동기화

먼저 알아둘 용어와 정의

코드 전체를 외우기보다, 각 이름이 무엇을 가리키는지 연결해서 읽어 보세요.

state
컴포넌트가 렌더 사이에 기억하는 값입니다. 이 예제의 count는 App에 있습니다.
set 함수와 렌더
setCount로 다음 값을 요청하면 React가 컴포넌트 결과를 다시 계산하고 필요한 화면 변경을 반영합니다.
업데이트 함수
setCount(c => c + 1)처럼 이전 값으로 다음 값을 계산하는 함수입니다. 같은 이벤트에서 여러 갱신을 연결할 때 중요합니다.
props와 콜백
App은 count를 Header에, handleAdd 함수를 onAdd라는 props로 MenuCard에 전달합니다. 자식은 받은 함수를 호출해 알립니다.
Effect와 의존성 배열
useEffect는 렌더가 반영된 뒤 외부와 맞추는 일을 합니다. [count]는 처음과 count가 달라진 커밋 뒤 동기화하게 합니다.
스냅샷과 불변성
한 렌더에서 읽는 state는 그 렌더의 값입니다. 객체 state를 바꿀 때는 직접 고치지 않고 새 객체를 만들어 전달합니다.
정리 함수
Effect가 시작한 타이머·구독 등을 해제하기 위해 반환하는 함수입니다. 관련 Effect 재실행 전과 제거 때 실행합니다. 이 제목 변경 예제에는 타이머가 없습니다.

꼭 기억할 내용

  • 값 하나를 여러 컴포넌트가 함께 쓰므로 공통 부모 App이 기억합니다. 각 카드가 별도 총개수를 기억하도록 만들면 값이 어긋날 수 있습니다.
  • onClick={onAdd}는 함수를 전달하고 onClick={onAdd()}는 렌더 중 호출합니다. state 변경 함수가 즉시 실행되면 반복 렌더 오류가 날 수 있습니다.
  • 화면에 계산해서 보여 줄 수 있는 값은 별도 state와 Effect로 복제하지 않는 편이 단순합니다.
  • 이 예제는 총 담은 개수만 기억합니다. 메뉴별 수량이나 실제 주문·결제까지 구현한 것은 아닙니다.
이 예제의 코드를 읽는 순서
  1. 처음 count는 0이며 Header가 0개를 표시합니다.
  2. MenuCard 버튼을 누르면 props로 받은 onAdd를 호출합니다.
  3. App의 handleAdd가 이전 값에 1을 더하는 갱신을 요청합니다.
  4. 새 count로 렌더한 결과가 Header에 반영됩니다.
  5. [count] Effect가 문서 제목을 맞추며 미리보기 제목과 콘솔에서 확인할 수 있습니다.

자주 헷갈리는 부분

setCount 바로 뒤의 count는 새 값일까요?

같은 핸들러가 읽는 값은 해당 렌더의 스냅샷입니다. 다음 렌더에서 새 값을 읽습니다.

[] Effect는 앱 전체 수명 동안 딱 한 번일까요?

마운트 때 실행하며 제거 후 다시 마운트하면 다시 실행할 수 있습니다. StrictMode 개발 점검도 구분해야 합니다. 이 복습 예제는 StrictMode로 감싸지 않았습니다.

자식이 부모의 state를 직접 바꾸는 것일까요?

부모가 전달한 콜백을 자식이 호출하고, 부모의 코드가 갱신을 요청하는 흐름입니다.

실제 React와 JSX를 사용합니다. 로컬에 포함한 React와 변환 도구로 실행하며, 강의의 Vite 설치 절차를 재현한 것은 아닙니다. 화면 편집기에서 JSX도 바꿀 수 있습니다.

04. 복습문제

같은 이벤트에서 setCount(count + 1)을 두 번 부르면 2가 늘까?

내가 답한 뒤 해설 보기

같은 클릭에서 같은 스냅샷을 읽으면 1 증가한다. 업데이트 함수를 두 번 쓰면 앞 결과를 이어받아 2 증가한다.
