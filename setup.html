SETUP / 처음 실행하는 사람을 위한 안내

파일을 만들고,
내 컴퓨터에서 실행하기

브라우저 실습은 설치 없이 시작할 수 있습니다. 실제 폴더의 파일을 수정하거나 Node·React 프로젝트를 실행할 때는 아래 순서를 따르세요.

1. 내 파일을 만드는 최소 준비

  1. Chrome·Safari 등 최신 브라우저를 준비합니다.
  2. 코드 편집기를 준비합니다. Visual Studio Code 공식 사이트에서 운영체제에 맞는 설치 파일을 받을 수 있습니다.
  3. 바탕화면 등에 my-first-site 폴더를 만듭니다.
  4. 편집기의 ‘폴더 열기’로 해당 폴더를 엽니다. 파일 하나만 여는 것과 폴더 전체를 여는 것을 구분합니다.
  5. 새 파일을 만들고 이름을 index.html로 저장합니다. index.html.txt가 되지 않았는지 확인합니다.
  6. HTML 수업의 전체 예제를 넣어 저장하고 브라우저에서 이 파일을 엽니다.
  7. 문구를 바꾼 뒤 파일을 저장하고 브라우저를 새로고침합니다.

이 사이트 편집기의 ‘실행 HTML 받기’를 사용하면 실행 틀이 포함된 파일을 받을 수 있습니다. React 예제 파일은 현재 사이트의 라이브러리 주소를 사용하므로 완전한 로컬 개발은 React 프로젝트 ZIP을 사용합니다.

2. 터미널은 어느 폴더에서 실행할까요?

명령은 현재 폴더를 기준으로 파일을 찾습니다. VS Code에서 프로젝트 폴더를 연 뒤 ‘터미널 → 새 터미널’을 열면 위치를 확인하기 쉽습니다. 다음 명령은 파일을 지우거나 바꾸지 않고 현재 위치를 확인합니다.

macOS / Linux

pwd
ls

Windows PowerShell

Get-Location
Get-ChildItem

Node 프로젝트에서는 server.mjs 또는 package.json이 이 목록에 보이는지 확인하세요. 폴더를 이동할 때는 cd "폴더 경로"를 사용합니다. 공백이 있는 경로는 따옴표로 감쌉니다.

3. Node.js를 설치하고 확인하기

  1. Node.js 공식 다운로드에서 지원되는 LTS 설치 방법을 선택합니다.
  2. 설치가 끝나면 새 터미널을 열고 아래 명령을 실행합니다.
  3. 버전 문자열이 보이면 실행 환경이 준비된 것입니다. cafe-lab은 Node 22 이상, react-lab은 22.12 이상을 요구합니다.
  4. 명령을 찾지 못하면 설치 여부와 새 터미널의 경로 설정을 확인합니다. 서버 파일을 브라우저에서 여는 것으로 대신하지 않습니다.
node --version
npm --version

기존 프로젝트가 특정 Node 버전을 요구하면 그 프로젝트 요구를 우선 확인합니다. 여러 버전을 관리하는 nvm 같은 도구는 Node 레슨에서 역할을 설명합니다.

4. Node 서버를 처음 켜기

  1. cafe-lab ZIP을 받고 압축을 풉니다.
  2. 압축을 푼 cafe-lab 폴더를 편집기로 엽니다.
  3. 그 폴더 터미널에서 아래 명령을 실행합니다. 이 프로젝트는 외부 패키지 설치가 필요 없습니다.
  4. 터미널을 실행 중 유지한 채 브라우저에서 주소를 엽니다.
  5. 끝낼 때는 서버 터미널을 선택하고 Ctrl+C를 누릅니다. Command+C와 구분하세요.
node server.mjs

# 브라우저에서 열 주소
http://127.0.0.1:4177

4177이 이미 사용 중이면 어떤 프로그램인지 확인하거나 다른 포트를 선택합니다.

macOS / Linux

PORT=4200 node server.mjs

Windows PowerShell

$env:PORT = "4200"
node server.mjs

포트를 바꾸었다면 브라우저 주소도 http://127.0.0.1:4200으로 바꿉니다. 127.0.0.1은 현재 기기 자신입니다.

5. React 개발 프로젝트를 처음 켜기

  1. react-lab ZIP을 풀고 폴더를 엽니다.
  2. package.json이 보이는 터미널에서 의존 패키지를 설치합니다. 이때 인터넷이 필요합니다.
  3. 개발 서버를 실행하고 터미널에 출력된 Local 주소를 브라우저로 엽니다. 포트가 달라질 수 있으므로 실제 출력을 읽습니다.
  4. src/App.jsx를 수정하고 저장해 화면에서 확인합니다.
  5. 정상 동작 후 빌드하고 결과를 미리 확인합니다.
npm install
npm run dev

# 개발 서버를 끝내고 배포 결과를 확인할 때
npm run build
npm run preview

npm install은 패키지 준비, dev는 개발 서버, build는 배포 파일 생성, preview는 생성 결과 확인입니다. 같은 단계로 외우지 마세요.

6. Git과 GitHub를 처음 연결할 때

GitHub Desktop 같은 GUI 도구로도 변경 비교·커밋·push를 수행할 수 있습니다. 터미널 명령을 쓸 때는 git --version으로 사용 환경을 확인합니다.

  1. 본인 계정의 저장소와 로컬 프로젝트의 연결을 확인합니다.
  2. 변경 파일과 diff를 읽고 실제 비밀·개인 데이터가 섞이지 않았는지 봅니다.
  3. 작업 목적이 드러나는 메시지로 커밋합니다.
  4. Push origin으로 원격에 전송합니다.
  5. Pages 또는 Actions의 배포 상태와 실제 공개 주소를 확인합니다.

설정·권한·공개 범위를 이해한 뒤 본인 저장소에 연결합니다. 커밋했다고 자동으로 원격·배포까지 완료된 것으로 판단하지 않습니다.
