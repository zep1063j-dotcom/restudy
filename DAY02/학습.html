회원가입 폼 만들기

이 페이지의 코드는 강의 개념을 바탕으로 새로 구성한 연습 예제입니다.

전체 목차예제만 새 탭에서 열기

01. 핵심 개념

action·method·name, label, 입력 type, required

02. 실행 흐름

입력 → 브라우저 검증 → 정상적인 폼 제출이라면 지정 주소로 값 전송. 화면만 있어도 가입 처리가 구현된 것은 아니다.

먼저 알아둘 용어와 정의

코드 전체를 외우기보다, 각 이름이 무엇을 가리키는지 연결해서 읽어 보세요.

form
사용자 입력을 한 묶음으로 다루는 요소입니다. 기본 제출에서는 action이 보낼 주소, method가 전송 방식을 정합니다.
input과 type
input은 값을 받는 입력 요소입니다. type="email"·"password" 등에 따라 입력 방법과 브라우저의 기본 검사가 달라집니다.
label / for / id
label은 입력칸의 이름입니다. label의 for와 input의 id가 같으면 라벨을 눌러 해당 입력칸으로 이동할 수 있습니다.
name과 value
name은 일반 폼 제출에서 쓸 데이터 이름이고 value는 입력된 값입니다. id만 있고 name이 없으면 일반 폼 제출의 이름·값 쌍에 포함되지 않습니다.
required / minlength
required는 필수 입력, minlength는 최소 글자 수를 정합니다. 브라우저가 도와주는 검사이며 서버 검사도 따로 필요합니다.
submit / preventDefault
submit은 폼 제출 이벤트입니다. event.preventDefault()는 기본 제출 동작을 막아 JavaScript가 결과를 처리하게 합니다.

꼭 기억할 내용

  • 이 예제는 입력 형식을 확인할 뿐, 회원을 서버에 등록하거나 비밀번호를 저장하지 않습니다.
  • POST는 데이터를 요청 본문에 담는 방식이며, 그 자체가 암호화는 아닙니다. 실제 서비스의 전송 보호에는 HTTPS가 관련됩니다.
  • 사용자가 적은 input.value는 type="number"인 경우에도 문자열입니다. 숫자 계산은 별도의 변환을 확인하세요.
이 예제의 코드를 읽는 순서
  1. email과 pw 입력칸에서 type, required, minlength를 찾습니다.
  2. 가입 확인 버튼을 누르면 form의 submit 이벤트가 발생합니다.
  3. 브라우저 기본 검사를 통과한 경우 콜백이 실행되고 기본 제출을 막습니다.
  4. 이메일 값을 읽어 result의 글자를 바꿉니다.

자주 헷갈리는 부분

placeholder가 있으면 label은 없어도 될까요?

placeholder는 입력하면 사라지는 힌트입니다. 입력칸의 이름을 대신한다고 생각하지 마세요.

required를 넣으면 잘못된 입력을 완전히 막을까요?

브라우저 편의 검사입니다. 서버가 받는 값은 서버에서도 검증해야 합니다.

03. 직접 바꿔 보기

이메일을 빈칸으로 제출한 뒤 잘못된 주소를 넣어 보세요. 비밀번호 minlength를 6에서 8로 바꾸세요.

먼저 결과를 예상하고 한두 줄만 바꿔 보세요. 화면 편집 내용은 이 브라우저에 자동 저장됩니다. 브라우저가 저장을 제한하면 저장되지 않을 수 있습니다.

04. 복습문제

id는 있는데 name이 없으면 일반 폼 전송에서 어떤 문제가 생길까?

내가 답한 뒤 해설 보기

일반적인 폼 제출의 이름·값 쌍에 포함되지 않는다. id는 label 연결·요소 선택 등에 쓰이고 name이 전송 이름이다.
